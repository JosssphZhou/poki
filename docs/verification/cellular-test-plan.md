# 跨网连接验证

## 自动检查的新增关口

主测试：通过 MCP 读取跨网设备，关闭客户端并重启 Poki 服务，再以新客户端读取同一设备。

1. 保护用户可见的连续使用：客户端断开或 Poki 服务重启不会销毁已有手机连接。
2. 如果每条命令或每个 MCP 客户端重新启动原生连接，模拟手机关闭新连接入口后，第二次截图会失败。
3. 现有测试只覆盖 USB 和模拟器，没有 RemotePairing 会话生命周期。
4. 使用现有 MCP 集成测试入口与 beforeStart 夹具，不添加仅测试使用的生产开关。

真机检查：Wi-Fi 建连后拔 USB，切蜂窝，截图、启动应用、精确输入小写字母加数字、大小写混合文字、中文，核对输入并清空。另测明确重建隧道，以及完整连接丢失后的恢复。测试文字不得提交。

所有操作指定同一台授权 iPhone。Karing 设置与原有常驻 Poki 服务保持原状。

## 工具目录契约调整

现有三个协议测试分别覆盖默认客户端与 HTTP、全量 HTTP 与 stdio 配置、独立 Poki Agent 客户端。完整目录增加 `reconnect_device` 和 `disconnect_device`，因此总数从 56 改为 58。

1. 保护三个实际入口都能发现完整维护工具，默认任务目录仍保持精简。
2. 漏注册维护工具或错误沿用默认过滤目录，会使总数和工具可用性断言失败。
3. 三个入口具有不同的工具过滤和配置传播行为，沿用现有契约测试，不另加重复测试文件。
4. 全部经真实 MCP 发现入口检查，不新增生产注入点。
